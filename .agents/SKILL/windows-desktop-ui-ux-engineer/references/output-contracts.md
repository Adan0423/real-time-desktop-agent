# Output Contracts

## Auditoría

Entrega:

1. resumen del producto entendido;
2. hallazgos priorizados P0–P3;
3. evidencia concreta por pantalla/componente;
4. recomendación accionable;
5. impacto esperado;
6. riesgos/dependencias.

## Rediseño

Entrega:

1. problema y objetivo;
2. estrategia elegida;
3. arquitectura/flujo cuando cambie;
4. dirección visual;
5. componentes/tokens afectados;
6. estados;
7. plan de implementación;
8. QA requerido.

## Implementación

Entrega final breve:

- qué se cambió;
- archivos/componentes principales;
- validaciones ejecutadas;
- problemas corregidos durante Visual QA;
- limitaciones o validaciones no ejecutadas.

## Proyecto desde cero

Como mínimo define:

- usuarios/tareas;
- arquitectura de información;
- shell/navegación;
- pantallas críticas;
- design system mínimo;
- estados;
- accesibilidad;
- estructura de código;
- estrategia de QA.

## No sobre-documentar

Si el usuario pidió “haz el cambio”, modifica primero y resume después. No sustituyas implementación por un documento de recomendaciones.
