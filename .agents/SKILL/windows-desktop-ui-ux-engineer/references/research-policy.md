# Research Policy

## Objetivo

Investigar únicamente cuando reduce incertidumbre o mejora una decisión actual.

## Disparadores

Busca información externa si:

- una API/framework puede haber cambiado;
- necesitas confirmar soporte de una capacidad;
- el usuario pide “actual”, “moderno”, “mejor práctica” o comparación;
- no existe suficiente evidencia local para elegir un patrón UX;
- la accesibilidad o compatibilidad depende de documentación normativa;
- se evalúa introducir una librería/dependencia;
- la tarea incluye benchmarking de productos o competencia.

## Jerarquía de fuentes

1. Documentación oficial de plataforma/framework.
2. Design systems oficiales.
3. Repositorios oficiales y release notes.
4. Estándares técnicos/accesibilidad.
5. Casos de estudio/documentación de productos comparables.
6. Artículos secundarios, solo como apoyo.

## Baseline Windows

Como punto de partida, prioriza documentación actual de:

- Microsoft Learn — Windows app design guidelines.
- Microsoft Learn — Windows App SDK / WinUI 3.
- Microsoft Learn — Windows accessibility.
- Fluent Design / Fluent 2 resources cuando sean pertinentes.

No congeles la skill a una versión específica. Verifica la documentación vigente cuando la decisión dependa de actualidad.

## Investigación competitiva

No copies interfaces literalmente. Extrae:

- arquitectura de tareas;
- patrones recurrentes;
- convenciones de navegación;
- manejo de densidad;
- errores frecuentes;
- oportunidades de diferenciación.

Separa “patrón útil” de “estética de moda”.

## Resultado de investigación

Convierte investigación en decisiones accionables. No vuelques enlaces sin síntesis.

Para cada hallazgo relevante, responde internamente:

- ¿Qué decisión cambia?
- ¿Qué evidencia la soporta?
- ¿Aplica a este stack/usuario?
- ¿Cuál es el costo o tradeoff?
